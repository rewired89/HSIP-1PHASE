How it works

Three calls to get started. No data migration, no agents to install.

Hash and send

Your system hashes the decision record and sends the hash with an actor and an action. The content stays with you.

We sign and chain

The hash is stamped with the time, signed by your organization's key, and linked to the previous record in its stream. Batches are anchored about every minute.

Anyone can verify

Share a link or export an evidence pack. Verification is a pure function that runs offline against open-source code.

What you get

The properties auditors ask for, built into the format rather than promised in a policy.

Tamper-evident by construction

Each record is signed and chained to the one before it. Editing, deleting or reordering anything breaks the chain in a way anyone can detect.

Your data stays with you

You send a SHA-256 fingerprint, not the record. The content of your decisions never reaches HSIP.

Independent verification

Auditors verify with an open-source tool, offline, with no account. To know whose records they are, they compare the signing key with the one the organization publishes.

Time evidence

Records are batched into signed Merkle trees and can be committed to Bitcoin through OpenTimestamps. The Bitcoin proof is checked with an OpenTimestamps client.

Evidence packs on demand

Export a signed, complete, verifiable record of a period for a regulator, a counterparty or a court, plus a printable report.

Built for teams

Streams per system, scoped API keys, owner, admin, developer and auditor roles, and a signed audit trail of the platform's own actions.

What a proof covers

A proof is evidence for a reviewer, not a verdict. Each question below has its own answer, and the verifier shows each check separately.

A reviewer asksCovered today?What a pass shows
Are these the bytes that were recorded?YesThe record matches its signed hash.
Who signed it?PartlyIt was signed by the key written in the file. Compare that key with the one the organization publishes.
Is it in a signed batch?YesIncluded in a Merkle batch with a signed root.
Is the history unbroken?PartlyRecords link by hash and a removed record shows up in an exported pack. Rollback of the newest records is not detected yet.
When did it exist?PartlyThe file reports its time-evidence state. A Bitcoin proof, if present, is checked with an OpenTimestamps client.
Was everything recorded?NoA proof cannot show an action that was never recorded. Each pilot starts with a written capture boundary.
Was the decision right or lawful?NoEvidence for review only.

The full wording is in what a proof covers, and a capture boundary template is public.

Honest about the limits

A proof shows that a record existed in this exact form at a point in time, was signed by a key, and has not been changed, removed or reordered since. It does not show that the decision was right, and it does not make a system compliant with any rule.

What a pass means

The offline check proves a record is unaltered and was signed by the key written in the file. It does not prove whose key that is, so compare it with a key the organization publishes. The anchor time is reported by the file, and the Bitcoin timestamp has to be checked with an OpenTimestamps client.

What is not built yet

HSIP records and proves. It does not yet stop an agent before it acts. By default the platform holds each organization's signing key; a key you hold yourself is available and one-way. No independent security audit has been completed yet. The platform runs from the open source today and pilots are set up by arrangement.
