# CODEMAP

Entries cover the HSIP platform code. The Phase 2 protocol crates are untouched and are not mapped here. Format: **purpose**, `calls`, `called_by`, `mutates`.

## crates/hsip-proof (open format + verifier, no I/O)

- `src/lib.rs` Signatures are checked with `verify_strict` and small-order public keys are rejected (`vk_from_b64`).
- `time_evidence(bundle)` in `crates/hsip-proof/src/lib.rs`: reports a record's external-time state without checking it; `Verification.time_evidence` and `PackVerification.time_summary` carry it to the CLI (`[TIME]` line), wasm and API. Fixtures: `docs/examples/prove/sample-evidence-pack-removed-record.json` (must fail). Docs: `docs/PROVE_CLAIMS.md` (what a proof covers), `docs/CAPTURE_BOUNDARY_TEMPLATE.md`, `docs/examples/prove/README.md`.
- `crates/hsip-proof/src/checkpoint.rs` `hsip-checkpoint/1`: `Checkpoint`, `sign_checkpoint`, `verify_checkpoint`, `check_checkpoints` (pack vs checkpoints the customer kept: consistent, different_history, tail_missing, wrong_key...), `check_checkpoint_set` (two heads for one position, head moved backwards), `check_checkpoints_text` (shared by CLI `checkpoint-check` and wasm `check_checkpoints`). Platform: `checkpoints.rs` (`record_heads` called by `anchor::run_cycle` after each batch; table `checkpoints`, UNIQUE(stream_id, seq); signed with the org platform key), `routes/checkpoints.rs` (`list_stream` console, `list_api` read key). Fixtures: `docs/examples/prove/sample-checkpoint*.json` made by `crates/hsip-proof/examples/gen_checkpoint_samples.rs`. Proof Check page card "Check against checkpoints you kept".
  - `Envelope` the signed statement (format `hsip-proof/1`). `canonical_bytes`/`event_hash` JCS + SHA-256. `sign_envelope(env, key)` returns `(event_hash_hex, signature_b64)`. called_by: `platform::engine::record`, tests.
  - `ProofBundle`, `AnchorBlock`, `ProofStepDto` wire types for a proof and its batch evidence.
  - `verify_bundle(&ProofBundle) -> Verification` checks content hash, signature, format, Merkle inclusion, anchor signature. called_by: `routes::{proofs,public}`, `evidence`, CLI.
  - `payload_matches(bundle, content)` SHA-256 compare of original content with `payload_hash`.
  - `PackManifest`, `EvidencePack`, `sign_manifest`, `manifest_hash`, `verify_pack` signed export: manifest hash/signature, manifest vs proofs, per-proof validity, single issuer, contiguous chain.
- `src/merkle.rs` RFC 6962 `MerkleTree` (`from_leaves`, `root`, `inclusion_proof`), `verify_inclusion`, `leaf_hash`/`node_hash`. called_by: `platform::anchor`, `engine::bundle_for`, `lib::verify_bundle`.
- `src/bin/hsip_proof.rs` `hsip-proof verify <file>` offline verifier for a bundle or pack; exit 0 valid, 1 invalid, 2 usage.
- `tests/samples.rs` pins `docs/examples/prove/*.json`; a failure is a breaking format change.

## crates/hsip-platform/src

- `main.rs` boots config, `AppState`, spawns `anchor::spawn`, serves `app(state)`.
- `lib.rs` `app(state)` = `routes::api` + console fallback (`ui::serve`) + security header layers.
- `config.rs` `Config::from_env` (all `HSP_*`, `DATABASE_URL`, `PORT`), `Config::for_tests`.
- `state.rs` `AppState` (pool, config, master key, anchor key, org key cache, throttle). `org_signing_key(org)` decrypts and caches; `allow(bucket, limit, window)` fixed-window limiter; `sweep_throttle_if_due`. Creates the master key file (0600) and the `anchor_identity` row. mutates: `anchor_identity`. `allow` keeps at most 200,000 live rate-limit windows and refuses new keys at the cap.
- `db.rs` `connect` (sqlx Any, runs `run_migrations`), `SCHEMA` (all tables), `now_ms`, `ms_to_iso`, `month_key`. Portability rules in header comment.
- `crypto.rs` `encrypt_secret`/`decrypt_secret` (ChaCha20-Poly1305, HKDF), `sha256_hex`, `random_token(prefix)`, `hash_password`/`verify_password` (Argon2id), `ct_eq`.
- `errors.rs` `ApiError` (400/401/402/403/404/409/429/500), converts sqlx/anyhow errors without leaking text.
- `auth.rs` `Role`, `bearer`, `session_user`, `member(state, headers, org)` (404 for non-members), `Member::{require_admin,require_write,require_owner,actor}`, `api_key` (+rate limit, touches `last_used_at`), `operator`, `client_ip`. Failed authentication (unknown or revoked API key, API key rate limit, rejected operator key) logs a `warn` with the client IP, never the secret. `client_ip` reads only `CLIENT_IP_HEADER`, which the `resolve_client_ip` middleware in `lib.rs` sets on every request from `HSP_CLIENT_IP_HEADER` (a trusted proxy header such as Fly's `fly-client-ip`, parsed as an IP) or else the socket peer address, or `local` when there is no socket. `X-Forwarded-For` is never read.
- `engine.rs` core. `record(state, NewProof)` validates, enforces org status + plan limit, signs with the org key, chains with retry on unique violation, bumps `usage_monthly`. mutates: `proofs`, `usage_monthly`. called_by: `routes::proofs`, `audit::log`. `bundle_for(db, row, org, cache)` rebuilds a bundle with Merkle path (`AnchorCache` per request). `prepare(state, NewProof)` and `commit(...)` implement customer-held keys (the customer signs `event_hash`; `commit` verifies it against `organizations.customer_verify_key`, checks the ±300s window and that seq/prev_hash equal the current tip, then inserts with `signer_key`). `record` refuses user streams for such orgs (409). `fetch_proof`, `org_info`, `month_usage`, `ProofRow`, `ProofSummary`, `PROOF_COLS`.
- `audit.rs` `log(state, org, actor, action, subject, detail)` best-effort proof into the org's system stream. called_by: most mutating routes.
- `anchor.rs` OpenTimestamps client (ported from the retired Phase 1 repo: `submit_digest_to`, `check_for_upgrade`, `extract_pending_calendar_uri`, `contains_bitcoin_attestation`), `run_cycle` (batch unanchored proofs into a Merkle tree, sign root with anchor key, optional OTS, atomic claim), `retry_unreachable`, `run_upgrade_cycle`, `spawn` (5 s due-check loop, 15 min upgrade loop). mutates: `anchors`, `proofs.anchor_id/merkle_index`.
- `qb.rs` `Where` builder (`eq_s`, `cmp_i`, `contains_any`, `raw`) and `bind_args` for dynamic filters on both backends.
- `plans.rs` `PLANS`, `get(id)`, `exists(id)`; limits and display prices (Team 79, Business 399 USD/month; still display-only, no processor). `SERVICES` enterprise catalogue (`available`/`on_request`/`roadmap`, incl. `case_pack`, `partner`), `service_exists`.
- `report.rs` `render(...)` printable HTML evidence report (escaped, CSP meta).
- `ui.rs` `serve(uri, dir)` console static files (embedded with `embed-console`, else from disk), SPA fallback, no path traversal.

### routes/ (all registered in `routes/mod.rs`)

- `account.rs` signup (also records a `signup` lead), login, logout, me, `create_org` (key + owner + system stream), invite preview/accept, new org. mutates: `users`, `sessions`, `organizations`, `memberships`, `streams`, `invites`. Login checks a dummy Argon2 hash when the email is unknown, so a miss costs what a hit costs; failed and throttled sign-ins log a `warn` with the client IP.
- `orgs.rs` get org (+ usage, role), rename, `usage`, `overview` (stats, 24 h/30 d buckets, top actions/actors), `request_plan` (lead), `request_service` (`service_request` lead, admin only), `fingerprint(vk)`, `set_custody` (owner registers a customer public key after `verify_registration`; audit `org.custody_enabled`/`rotated`; `get` returns `custody`).
- `streams.rs` list (with stats), create (plan stream limit), update/archive (admin).
- `proofs.rs` `ingest`, `ingest_prepare`, `ingest_commit`, `ingest_batch`, `api_get` (API key); `console_record`, `list` (filters, paging), `get_one`, `create_share` (needs the write role, so auditors cannot publish links), `list_shares`, `revoke_share`, `integrity` (recompute a stream's chain). `integrity` is limited to 6 per minute per organization and stops at 100,000 records (`complete: false`).
- `keys.rs` list/create/revoke API keys (admin). Raw key returned once.
- `team.rs` members list, invite (seat limit), revoke invite, set role, remove; last-owner guards. `invite` is limited to 20 per hour per organization and 3 per day per recipient, and strips control characters from text placed in the email.
- `evidence.rs` create (self-verifies before release, plan size cap), list, `pack` (JSON), `report_html`. mutates: `evidence_exports`.
- `public.rs` health, meta, `verify`, `match_content`, `view_share`, `org_key`, `lead`. No auth on verify.
- `operator.rs` overview (owner email, last proof, usage per org), `set_plan`, `set_status` (suspend), leads (`signup`, `contact`, `plan_request`, `service_request`). Gated by `HSP_OPERATOR_KEY`.

### tests/

- `common/mod.rs` helpers (`env`, `env_with`, `call`, `signup`, `stream`, `api_key`, `ingest`, `hash_of`).
- `integration.rs` 9 tests: signup rules, full record/anchor/verify/share/evidence flow, DB tampering detection, roles + isolation, key scopes, plan limits + operator, filters + overview, login throttle, concurrent chain safety.
- `access_matrix.rs` every session route called as no login, outsider, auditor, developer, admin and owner; fails when a role check is missing. A second test reads `routes/mod.rs` and fails when a route is registered without a matrix entry or an `EXEMPT` entry. A third checks that session tokens, API keys and the operator key are not interchangeable. Add a row here whenever you add a route.
- `crates/hsip-verify-web/smoke.test.mjs` Node test of the compiled verifier in `verifier/pkg` (sample proof and pack verify, altered record fails, garbage never throws, permission typo rejected). CI job `sdks-and-verifier` runs it with the SDK tests.
- `postgres_compat.rs` same core flow on real PostgreSQL (ignored unless `HSP_TEST_POSTGRES_URL`).

## Other

- `examples/predicta/hsip_client.py` drop-in connector for Predicta's `attest_transaction` call on the current platform (`POST /v1/ingest`); `examples/predicta/demo.py` runs six Predicta-shaped trades through it, signs a permission and shows violations plus the offline re-check.
- `crates/hsip-proof/src/mandate.rs` `Mandate`/`MandateBody`/`Rules` (`Rules`, `RateRule`, `AmountRule` reject unknown keys, so a misspelled rule fails instead of silently allowing everything; `MandateBody` cannot, because it is flattened into `Mandate`), `sign_mandate`, `verify_mandate`, `evaluate` (rules: allowed_actions, time window, max_per_period, max_amount on a metadata field, allowed_values; reports `Violation`s), `proofs_from_value`. CLI `hsip-proof mandate-sign`/`mandate-check`. `routes/mandates.rs` `create`, `list`, `revoke`, `report` (table `mandates`); console `pages/Permissions.jsx` (list, add a signed permission, check a stream, revoke; route `/permissions`); wasm `check_permission`, `sign_permission`, `public_key` power the Proof Check page's "Create a permission" form (key from the browser's secure random generator, signed in the page, nothing sent anywhere) and permission box.
- `crates/hsip-verify-web/src/lib.rs` `verify(text)` (wasm-bindgen export) and `verify_text`: dispatch a pasted bundle or pack to `hsip_proof::verify_bundle`/`verify_pack`; pure, returns JSON. Built with `hsip-proof` default features off (no `keygen`/`rand`). `.github/workflows/pages.yml` assembles `site/` (landing page at the root), `verifier/` (served at `/check/`) and `docs/examples/prove/*.json` (served at `/samples/`) and deploys them to GitHub Pages. `site/index.html` is the static landing page in the console's design (links `console.css`, copied from `console/src/styles.css` by the workflow; CSP, no scripts; honest limits listed; pilot by email). `verifier/index.html` is the static page, styled with the console's stylesheet (`console.css`, copied next to it by the Pages workflow; CSP blocks all outside requests; samples embedded; the verdict shows the signing key written in the file and says it must be compared with the organization's published key, and that anchor time is reported, not proven); `verifier/pkg/` is the generated wasm.
- `hsip-proof` also exposes customer-key helpers: `generate_signing_key`, `verify_key_b64`, `registration_digest`/`sign_registration`/`verify_registration`, `verify_hash_signature`, `check_prepared`; CLI `keygen`, `register-proof`. `PackManifest.issuer_keys` lists extra signer keys.
- `sdk/prove-python/hsip_prove.py`, `sdk/prove-node/index.mjs` ingest/read/verify clients; identical `hash_payload` output across languages for ASCII keys.
- `docs/PROVE_PLATFORM.md`, `docs/PROVE_PROOF_FORMAT.md`, `docs/examples/prove/` (real fixtures).
- `Dockerfile.platform`, `docker-compose.platform.yml`, `.env.platform.example`, `.github/workflows/prove.yml`. `fly.toml`: Fly.io app config (build from `Dockerfile.platform`, `HSP_CLIENT_IP_HEADER=fly-client-ip`, `/data` volume mount `hsip_data`, always-on machine, `/health` check). Secrets are set with `fly secrets set`; nothing is deployed.

- `sdk/prove-action/` GitHub Action (`action.yml`, `record.mjs`): hashes a file or the commit SHA locally and records it via the Node SDK. `docs/PROVE_AI_ACT_LOGGING.md`: recording template for high-risk AI decisions.

Console: `Billing.jsx` Upgrade and Manage subscription.
